# 🐷 아기돼지 삼형제 메타버스 동화 게임 — 정책서

문서 버전 v1.0 | 관련 문서: 01_기획서.md, 02_기능명세서.md

본 정책서는 만 4세 아동을 대상으로 하는 3D/웹캠 기반 콘텐츠의 특수성을 고려하여, 개발·운영 전반에서 반드시 지켜야 할 원칙을 규정합니다.

---

## 1. 콘텐츠 등급 및 정서 안전 정책

| 항목 | 정책 |
|---|---|
| 목표 등급 | 전체 이용가 수준, 만 4세 기준 공포/자극 요소 최소화 |
| 늑대 캐릭터 표현 | 위협적 실루엣 금지. 둥글고 배가 나온 코믹한 형태만 허용. 이빨은 과장된 카툰풍으로 표현하되 사실적 공포 이미지 사용 금지 |
| 사운드 톤 | 늑대 등장 BGM은 "장난스러운 마이너 코드/트롬본"까지만 허용, 실제 공포영화식 저음 스트링/서든 스팅어(jump-scare) 사용 금지 |
| 실패 연출 제한 | 캐릭터가 다치거나 잡히는 연출 금지. 집이 부서지는 것은 "날아가는" 형태로만 표현, 파괴 잔해가 캐릭터를 향해 날아오는 연출 금지 |
| 정서 마무리 원칙 | 모든 위기 장면은 반드시 안전하고 밝은 장면으로 종료되어야 하며, 화면이 어둡거나 긴장 상태로 끝나는 시퀀스를 금지 |
| 나레이션 톤 | 실패/오작동 시에도 부정적 어휘("틀렸어요", "실패") 사용 금지, 항상 격려형 문구 사용 |

## 2. 웹캠(카메라) 사용 및 아동 개인정보 보호 정책

아동을 대상으로 카메라를 사용하는 기능이므로 가장 엄격한 기준을 적용합니다.

| 항목 | 정책 |
|---|---|
| 권한 요청 | 미니게임 진입 직전에만 카메라 권한을 요청하며, 사용 목적을 아동/보호자가 이해할 수 있는 문구로 명시("팔을 흔들어 함께 도망쳐요!") |
| 영상 처리 방식 | 포즈 인식은 반드시 **기기 내(온디바이스) 처리**를 원칙으로 하며, 영상 데이터를 서버로 전송·저장하지 않음 |
| 저장 금지 | 웹캠 영상, 스냅샷, 캡처 이미지는 어떠한 경우에도 로컬/서버에 저장하지 않으며, 세션 종료 시 스트림을 즉시 해제(`stream.getTracks().forEach(t => t.stop())`) |
| 관절 좌표 데이터 | 실시간 렌더링 목적으로만 메모리상에서 사용, 별도 로깅·전송 금지 |
| 보호자 고지 | 최초 실행 시 보호자 대상 안내 화면(선택 사항)을 통해 카메라 사용 정책을 고지하는 것을 권장 |
| 거부 시 처리 | 카메라 권한을 거부하거나 기기가 미지원인 경우, 어떠한 불이익 없이 즉시 대체 조작(3회 탭)으로 동일한 진행이 가능해야 함 (기능명세서 3-7 폴백 로직 참조) |
| 제3자 SDK | 포즈 인식 라이브러리(TensorFlow.js/MediaPipe)는 클라이언트 사이드 오픈소스만 사용하며, 외부 분석/광고 SDK와 카메라 데이터를 공유하지 않음 |

## 3. 접근성(Accessibility) 및 폴백 정책

| 항목 | 정책 |
|---|---|
| 입력 대체 수단 | 모든 웹캠 기반 인터랙션은 반드시 터치/탭 기반 대체 수단을 함께 제공(필수, 선택 아님) |
| 시간 제한 | 미니게임 등에서 30초 이상 진행이 없을 경우, 좌절감을 주지 않도록 자동으로 대체 UI 노출 |
| 색각 다양성 고려 | 형제 구분은 색상뿐 아니라 형태(모자/멜빵/앞치마 등 실루엣 차이)로도 구분 가능하도록 설계 |
| 자막/음성 병행 | 모든 대사는 자막(텍스트) + 음성(TTS/성우)을 함께 제공하여 난청 아동도 진행 가능하도록 함 |
| 조작 난이도 | 정밀한 드래그가 어려운 유아 특성을 고려해 오브젝트 스냅 판정 범위를 넉넉하게 설정(느슨한 히트박스) |

## 4. 멀미(Motion Sickness) 방지 정책

VR/1인칭 콘텐츠는 유아에게 어지러움을 유발할 수 있으므로 아래 기준을 엄수합니다.

| 항목 | 정책 |
|---|---|
| FOV | 75~80도 고정, 급격한 FOV 변화(줌인/줌아웃 포함) 최소화 |
| 카메라 이동 | 자동 보행 시 헤드밥 진폭을 최소화, 워크사이클 흔들림은 좌우 최대 8도 이내로 제한 |
| 강제 시점 회전 | 사용자 의사와 무관하게 카메라를 강제로 빠르게 회전시키는 연출 금지(예: 급격한 컷씬 회전) |
| 카메라 셰이크 | 늑대 습격 시에도 셰이크 강도는 약~중 수준으로 제한(재료별 차등 적용, 셋째 루트는 셰이크 없음) |
| 플레이 시간 권장 | 1회 플레이 세션 15분 이내 권장, 장시간 연속 사용 방지를 위한 안내 문구 고려 |

## 5. 난이도 및 실패 없는 진행 정책 (No-Fail Design)

| 항목 | 정책 |
|---|---|
| 기본 원칙 | 만 4세 대상 콘텐츠는 "실패"가 존재하지 않고, 모든 행동이 다음 이야기로 자연스럽게 연결되어야 함 |
| 미니게임 게이지 | 시간 제한으로 인한 실패 없이, 진행이 느려도 결국 완료 가능하도록 설계(폴백 대체 입력 포함) |
| 건축 미니게임 | 잘못된 위치에 오브젝트를 놓아도 자동 스냅으로 보정, 별도의 "오답" 판정 없음 |
| 재도전 | 언제든 캐릭터 선택 화면(씬B)으로 돌아가 다른 형제로 재시작 가능해야 함 |

## 6. 오디오/비주얼 표현 정책

| 항목 | 정책 |
|---|---|
| 폰트 | 아동용 둥근 고딕 계열, 최소 40px 이상, 두꺼운 컬러 테두리 필수(가독성 확보) |
| 색상 | 채도 낮은 파스텔톤 기본 + 포인트 컬러(분홍/하늘/노랑), 지나치게 어둡거나 채도 높은 원색 배경 지양 |
| 볼륨 기준 | BGM 대비 나레이션 음성이 항상 우선 청취 가능하도록 덕킹(ducking) 처리, SFX 급격한 고음/저음 스파이크 금지 |
| 파티클 강도 | 화면을 뒤덮는 과도한 파티클(플래시성 연출) 금지 — 광과민성 발작 예방을 위해 초당 3회 이상의 급격한 명멸 효과 사용 금지 |

## 7. 저장/진행 데이터 정책

| 항목 | 정책 |
|---|---|
| 저장 범위 | 게임 진행 상태(현재 씬, 선택 캐릭터, 게이지 진행도)만 로컬에 저장, 개인 식별 정보 저장 금지 |
| 자동 저장 시점 | 씬 전환마다 자동 체크포인트 저장 |
| 데이터 보관 기간 | 별도 정책이 없는 한 로컬 기기 내 세션 데이터로 한정, 서버 전송/보관하지 않음(웹캠 정책과 동일 원칙 적용) |

---

## 8. 운영/수업 시연 관련 정책

| 항목 | 정책 |
|---|---|
| 시연 환경 | 카메라/마이크 권한이 필요한 환경이므로, 시연 전 브라우저·기기 권한 상태를 사전 점검 |
| 대체 시나리오 | 웹캠 미지원 환경(발표장 PC 등)을 대비해 항상 탭 대체 모드로도 전체 플레이가 가능해야 함(필수 요구사항) |
| 콘텐츠 스킵 | 시연 시간 단축을 위해 각 대사 구간에 스킵 버튼을 기본 제공(정책 2-1 연계) |

---

## 9. 정책 준수 체크리스트 (배포 전 최종 점검용)

- [ ] 카메라 스트림이 세션 종료 시 확실히 해제되는가
- [ ] 웹캠 영상/이미지가 어디에도 저장되지 않는가
- [ ] 모든 웹캠 인터랙션에 탭 기반 대체 수단이 존재하는가
- [ ] 늑대 관련 연출에 실제 공포 요소(점프스케어, 사실적 공포음)가 없는가
- [ ] 실패로 인해 진행이 막히는 구간이 없는가
- [ ] 자막+음성이 모든 대사에 병행 제공되는가
- [ ] 초당 3회 이상의 급격한 명멸 파티클이 없는가
