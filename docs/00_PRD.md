## 1. 개요

**한 줄 기획.** 내가 직접 아기돼지 삼형제 중 한 마리가 되어, 1인칭 시점으로 숲속을 돌아다니며 집을 짓고 늑대를 피해 도망치는 3D 메타버스 동화.

기존 동화 콘텐츠는 대부분 "읽어주는" 수동적 감상에 머무른다. 이 프로젝트는 VR/3D 기술과 웹캠 모션인식을 결합해 아동이 몸을 움직이며 이야기에 직접 참여하도록 재구성한다. 수업 시연이라는 목적상, 짧은 시간 안에 기승전결이 뚜렷하고 상호작용 지점이 명확한 구조를 우선한다.

- **교육 목표** — "성실함과 꾸준한 노력의 가치"를 체험으로 전달하고, 팔 들어올리기 같은 대근육 운동을 미션과 연결한다.
- **핵심 재미** — 캐릭터 이입 → 손으로 짓는 집짓기 → 몸으로 도망가기 → 안전한 위기감 → 형제와의 재회.
- **차별화 포인트** — 선택→행동→결과의 상호작용, 웹캠 신체 인식, 캐릭터별 재플레이 가치, 실패 없는 설계.

## 2. 목표 & 성공 지표

기획서의 교육적 목표와 정책서의 세션 기준을 측정 가능한 지표로 변환했다. 정식 애널리틱스는 범위에 없으므로 시연 세션 관찰 및 수동 QA로 확인한다.

| 지표 | 목표값 | 근거 |
|---|---|---|
| 엔딩 도달률 | ≥ 90% | 시연 세션에서 씬I 엔딩까지 완주하는 비율 |
| 평균 세션 시간 | ≤ 15분 | 정책서 4장 권장 플레이 시간 |
| 대체 조작 성공률 | 100% | 웹캠 거부/미지원 시 탭 폴백으로 끝까지 진행 가능한 비율 |
| 정책 위반 | 0건 | 13장 체크리스트 중 배포 전 미해결 항목 수 |

## 4. 범위 & 로드맵

기획서 7장의 우선순위를 그대로 채택한다.

| 우선순위 | 포함 범위 |
|---|---|
| **Must** | 씬A(표지)~씬C(엄마 대화), 첫째 루트 전체(씬D~F, 짚집), 웹캠 도망 미니게임 1회, 씬I(엔딩) |
| **Should** | 둘째 루트, 셋째 루트(벽돌 2단계 제작) 전체 구현 |
| **Could** | 캐릭터 선택에 따른 대사 완전 분기, 재도전 후 다른 돼지로 이어보기 |

**현재 개발 환경 상태.** Vite + Three.js + TensorFlow.js(MoveNet) 스캐폴드가 구성되어 웹캠 신호 → 3D 씬 반응까지의 기술 파이프라인이 검증된 상태다. 씬 A~I의 서사·미니게임 로직은 아직 구현 전이다.

## 5. 사용자 흐름

모든 캐릭터 선택지는 최종적으로 "셋째의 벽돌집에서 다 함께 안전해지는" 동일한 결말로 수렴한다.

```
[씬A: 책표지] --들어가기--> [씬B: 캐릭터 선택(첫째/둘째/셋째)]
        │
        ▼ (선택한 돼지 기준으로 아래 공통 구조 반복/분기)
[씬C: 엄마와의 대화] → [씬D: 갈림길에서 헤어짐] → [씬E: 재료 채집·건축 미니게임]
        │
        ▼
[씬F: 늑대 습격 & 집 파괴] → [씬G: 웹캠 모션인식 도망 미니게임 (10칸 게이지)]
        │   (첫째, 둘째 루트에서만 발생 / 셋째는 최종 방어전으로 대체)
        ▼
[씬H: 다음 형제 집 도착 & 재회] → (다음 형제 루트 반복)
        │
        ▼
[씬I: 벽돌집 최종 방어(늑대 공격 실패)] → [엔딩: 축하 파티 + 도장 UI] → [씬A 복귀 / 다시하기]
```

| 시작 캐릭터 | 진행 순서 |
|---|---|
| 첫째(짚) | 첫째 루트 → 도망 미니게임① → 둘째 집 → 도망 미니게임② → 셋째 집(최종방어) → 엔딩 |
| 둘째(나무) | 둘째 루트 단독 전개 → 첫째가 찾아옴 → 도망 미니게임 → 셋째 집(최종방어) → 엔딩 |
| 셋째(벽돌) | 셋째 루트(벽돌 제작 2단계) → 형들이 찾아옴 → 문 잠그기 → 최종방어 → 엔딩 |

## 8. 씬별 기능 요구사항

| 씬 | 우선순위 | 핵심 명세 |
|---|---|---|
| A. 책 표지 | Must | y축 ±2cm 3초 부양, 레이캐스트/터치 조준 → 책 열림(1.2s) → 화이트아웃(0.5s) → 씬B |
| B. 캐릭터 선택 | Must | 3체 1.5m 간격, 시선/터치 3초 유지로 라디얼 프로그레스, `characterId` 저장 후 씬C |
| C. 엄마와의 대화 | Must | `characterId` 매핑 대사 순차 재생, yaw ±30°에서 idle-jump 반응, 스킵 가능 |
| D. 갈림길에서 헤어짐 | Must | 8초 walk-cycle 후 비활성화, `characterId`별 길 고정(좌/중/우) |
| E. 재료 채집·건축 | Must(첫째) / Should(둘·셋) | 첫째: 짚단 12~15개 스냅 3단계 → `buildComplete('straw')`. 둘째: 판자+못 3탭 → `buildComplete('wood')`. 셋째: 벽돌 6개 제작(진흙→다지기→가마)+쌓기 → `buildComplete('brick')` |
| F. 늑대 습격 & 파괴 | Must | 집 완성 2초 후 늑대 스폰, 숨불기(볼 1.0→1.6배), 재료별 강도 파괴(짚>나무>벽돌), Perlin noise 카메라 셰이크 |
| G. 웹캠 도망 미니게임 | Must | 좌 50% 3D 컷씬 / 우 50% 웹캠 미러. 손목 y가 어깨 대비 15% 이상 상승 시 `armUp`, 좌우 교대 1스텝, 10칸 게이지. **30초 미증가 시 3회 탭 폴백 필수** |
| H. 형제 재회 | Must | 문 두드림 → 문 열림 → 진입 애니메이션, 동행 리스트에 추가 |
| I. 최종 방어 + 엔딩 | Must | 자물쇠 1초 홀드, 늑대 공격은 반사 이펙트만(셰이크 없음), 2회 실패 후 퇴장, 콘페티 → 댄스 → 도장 UI |

## 9. 데이터 모델

씬 전환마다 자동 체크포인트로 저장되는 로컬 상태. 개인 식별 정보는 포함하지 않는다.

```json
{
  "gameState": {
    "characterId": "first | second | third",
    "currentScene": "E_build",
    "companions": ["first"],
    "gaugeProgress": 0,
    "checkpoints": {
      "lastSavedScene": "D_forest_split",
      "timestamp": "ISO8601"
    }
  }
}
```

| 필드 | 설명 |
|---|---|
| `characterId` | 최초 선택한 주인공 캐릭터 |
| `currentScene` | 현재 진행 중인 씬 ID |
| `companions` | 현재 동행 중인 형제 목록 |
| `gaugeProgress` | 미니게임 게이지 진행도(0~10) |
| `checkpoints` | 씬 전환 시 자동 저장되는 마지막 지점 |

## 10. 기술 스택 & 아키텍처

| 영역 | 선택 | 비고 |
|---|---|---|
| 렌더링 | Three.js | 기획서는 R3F/Babylon/Unity WebGL도 검토안으로 제시 — 저장소는 React 없이 순정 JS로 진행 중 |
| 빌드 도구 | Vite | 구성 완료, 프로덕션 빌드 검증됨 |
| 포즈 인식 | TensorFlow.js + `pose-detection`(MoveNet SinglePose Lightning) | webgl 백엔드 온디바이스 처리, `src/motion.js`에 구현 |
| 입력 | 자이로/드래그(시점) · 탭-투-무브 · 드래그/탭(상호작용) · 웹캠 포즈(미니게임 한정) | 모든 웹캠 입력은 탭 폴백 동반 필수 |
| 저장 | 로컬 스토리지 체크포인트 | 서버 전송 없음 |
| 사운드 | BGM(루프) + SFX + 나레이션 3레이어 믹싱 | 나레이션 우선 덕킹 처리 |

> **번들 크기 유의.** Three.js + TensorFlow.js 포함 프로덕션 빌드가 약 1.6MB(gzip 412KB)로 확인됨. 배포 전 동적 import 기반 코드 스플리팅 검토 필요.

## 11. 비기능 요구사항

정책서 1~7장을 기능 요구사항과 동일한 우선순위(Must)로 취급한다. 아동 대상 콘텐츠 특성상 협상 불가 항목이 많다.

**콘텐츠 등급 & 정서 안전**
- 늑대는 위협적 실루엣 금지, 코믹한 형태만 허용. 점프스케어·사실적 공포음 금지.
- 실패/오작동 시에도 부정 어휘 대신 항상 격려형 문구 사용.

**웹캠 & 아동 개인정보 보호**
- 포즈 인식은 기기 내 처리만 허용, 영상 데이터 서버 전송·저장 금지.
- 세션 종료 시 `stream.getTracks().forEach(t => t.stop())`로 즉시 해제.
- 카메라 거부/미지원 시 즉시 3회 탭 대체 조작으로 동일하게 진행 가능.

**접근성 & 폴백**
- 모든 웹캠 인터랙션은 터치/탭 대체 수단을 필수로 동반. 30초 무진행 시 자동 대체 UI 노출.
- 형제 구분은 색상뿐 아니라 실루엣으로도 가능. 모든 대사는 자막+음성 병행.

**멀미 방지**
- FOV 75~80도 고정, 헤드밥 좌우 8도 이내, 강제 시점 회전 금지. 세션 15분 이내 권장.

**난이도 & 무벌점 설계**
- 시간 제한으로 인한 실패 없음, 잘못된 배치도 자동 스냅 보정. 언제든 씬B로 재시작 가능.

**오디오/비주얼**
- 폰트 40px 이상 + 두꺼운 컬러 테두리. 초당 3회 이상 급격한 명멸 파티클 금지.

**저장/진행 데이터**
- 씬·캐릭터·게이지 진행도만 로컬 저장, 개인 식별 정보 저장 금지, 서버 전송 없음.

## 12. 리스크 & 미결 사항

세 기획 문서에서 명시적으로 다루지 않았거나, 구현 과정에서 확인이 필요한 항목이다.

- **포즈 인식 정확도** — 만 4세의 작은 팔 동작·불안정한 카메라 각도에서 MoveNet 임계값이 오탐/미탐할 수 있다. 실기기 테스트로 보정 필요.
- **초기 로딩 시간** — TensorFlow.js + Three.js 번들이 1.6MB 이상. 시연장 회선/기기 성능에 따라 로딩이 3초를 넘길 수 있다.
- **3D 아트 파이프라인 미정** — 로우폴리 캐릭터 5종·집 3종·소품의 제작 방식(직접 모델링/에셋 구매/생성형)이 문서에 명시되지 않았다.
- **VR 헤드셋 지원 범위** — 플랫폼에 VR 헤드셋이 명시되어 있으나 MVP는 모바일/PC 자이로·드래그 기준으로 기술되어, WebXR 실제 대응 여부가 불명확하다.
- **나레이션 음성 소싱** — TTS 대체 여부와 성우 녹음 여부에 따라 일정·비용이 크게 달라진다.
- **시연 환경 편차** — 발표장 PC의 웹캠 화각·조명·GPU 성능 편차가 크므로 사전 리허설이 필수적이다.

## 13. 출시 전 체크리스트

정책서 9장 원문을 그대로 채택한다. 모든 항목 충족이 배포 조건이다.

- [ ] 카메라 스트림이 세션 종료 시 확실히 해제되는가
- [ ] 웹캠 영상/이미지가 어디에도 저장되지 않는가
- [ ] 모든 웹캠 인터랙션에 탭 기반 대체 수단이 존재하는가
- [ ] 늑대 관련 연출에 실제 공포 요소(점프스케어, 사실적 공포음)가 없는가
- [ ] 실패로 인해 진행이 막히는 구간이 없는가
- [ ] 자막+음성이 모든 대사에 병행 제공되는가
- [ ] 초당 3회 이상의 급격한 명멸 파티클이 없는가
